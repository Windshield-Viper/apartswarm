# Does It Run in the Family? Lineage-Level Leniency When Language Models Monitor Code

Siddharth Gupta, Owen Tam, Saahir Vazirani — Apart Research Swarm Alignment Hackathon, November 2026 (Track A).

Seven open-weight models from four families (DeepSeek, Gemma, Qwen, GLM) each solved 34 small Python tasks honestly and with an instructed hidden objective (an inert telemetry call carrying the marker `CANARY-7F3A`). Each model then scored every submission for suspicion as a code reviewer blind to authorship, giving a 7x7 policy x monitor catch-rate matrix at per-pair 5% false-positive thresholds. Only the attacks are instructed; monitors are never told to be lenient.

**Headline results.** No robust general self-leniency: the pooled same-model effect (-0.134) is calibration-dependent. But the two Gemma models share a blind spot for Gemma-written attacks that survives matched false-positive rates, held-out calibration, a capability-adjusted block model, a structurally different attack class, stated authorship, paraphrase, and a reasoning-enabled probe. Tripling the benign calibration set raises the worst cell from 0.03 to 0.44 and halves the pooled family gap, but does not close it (own-family 0.47 vs cross-family 0.77).

## Reproduce every number

All model outputs are stored in `runs/` as JSONL; no API access is needed.

```
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
make recompute
```

Every number and figure in the paper regenerates into `analysis/out/`. `RUN_INDEX.md` maps each paper number to its run folder and command. Pre-registered hypotheses, with dated amendments, are in `PREREGISTRATION.md`.

## Repo map

```
tasks/        40 task specs + hidden pytest tests + utils.py (send_report is a logging no-op)
prompts/      frozen prompt templates + SHA-256 hashes (attack/polish prompts withheld, hashes kept)
runs/         one folder per run: scores.jsonl, submissions.jsonl, meta.json, frozen prompts
src/track_a/  pipeline: API client, policy/monitor runners, sandboxed test execution
analysis/     calibration, matched-FPR, GLM fits, permutation tests, robustness, figures
analysis/out/ committed results the Makefile regenerates (diff them to verify)
```

Key data formats: `runs/*/submissions.jsonl` has one record per (task, policy, condition, resample) with the generated code and test results; `runs/stage1_mon*/scores.jsonl` has one record per (submission, monitor, draw) with the 0-100 suspicion score and one-sentence reason.

## What is withheld, and why

This repository is a curated public snapshot. To limit reuse of the attack procedure, the attack and polish prompt texts and the code of successful attack submissions are withheld: redacted records keep all metadata (`"code": "[REDACTED - private appendix...]"`), so every aggregate number still reproduces. Two attack transcripts quoted in the paper remain in `analysis/out/full/excerpts.md`. The unabridged private repository — full commit history with timestamped pre-registrations (the hashes `RUN_INDEX.md` cites), the attack bank, prompts, and API usage logs — is available to hackathon judges on request.

## Provenance

Tasks were generated by glm-5.2 from fixed one-line specs and filtered (clean solution passes all hidden tests, deliberately wrong one fails). Claude Fable 5 (Anthropic) was the coding agent for the pipeline and analyses. All hidden-test execution of model-written code ran in a sandbox (subprocess, rlimits, timeouts, no network).
