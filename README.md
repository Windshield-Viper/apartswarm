# Does It Run in the Family? Lineage-Level Leniency When Language Models Monitor Code

Siddharth Gupta, Owen Tam, Saahir Vazirani — Apart Research Swarm Alignment Hackathon, November 2026 (Track 4)

Full writeup: [here!](https://docs.google.com/document/d/18ycncRjeO5qPKSrOFNEF6ZSSjGI4-hCheUqFJSYoSBM/edit?tab=t.0)

## Abstract

When one model in a multi-agent system reviews another's code, does the reviewer's identity matter? We measure whether open-weight LLMs acting as blind code reviewers go easier on code written by themselves or their own family. Seven models from four families (DeepSeek, Gemma, Qwen, and GLM) each solved 34 small Python tasks honestly and with an instructed hidden objective; each model then scored every submission for suspicion, as a monitor blind to authorship, giving a 7×7 policy × monitor catch-rate matrix at per-pair 5% false-positive thresholds. Crucially, only the attacks are instructed, and monitors are not instructed to show any leniency. We find no robust general self-leniency: the pre-registered pooled same-model effect (−0.134) is calibration-dependent. However, we find a blind spot in the Gemma models we tested that persists across matched false-positive rates, held-out calibration, a capability-adjusted block model, and a structurally different attack class: Gemma monitors catch 0.19–0.38 of Gemma-written attacks (own cells ~0.20) that cross-family monitors catch at 0.56–1.00. Stated authorship, paraphrase, and excuse-vocabulary analyses all fail to explain the lineage-level leniency. The practical implication for deploying agentic programming systems is that a monitor should be tested on its own family's code before it is trusted, and replace, rather than supplement, with a cheap cross-family model when it falls short. Future work can focus on testing additional lineages and larger families of frontier models, as well as utilizing interpretability tools and further testing to investigate why a blind spot runs in a family.
